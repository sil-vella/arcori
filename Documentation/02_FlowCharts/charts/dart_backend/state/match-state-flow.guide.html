Match State Flow

Plain English explanation and copy-paste examples for this flowchart.

This chart shows the join → play → broadcast → persist path on the Dart game server.

Join

Client sends match/join with optional match_id. Dart adds the player, registers the connection in RoomRegistry, and broadcasts the current snapshot.

Play

Client sends match/state patches (or server ticks in a future module). Each patch bumps version and is broadcast to all subscribers — other clients receive pushes without polling.

Leave / end

match/leave unsubscribes the connection. If the room is empty, Dart may mark the match ended and call FastAPI finalize.
