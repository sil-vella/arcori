Match State Flow

Plain English explanation and copy-paste examples for this flowchart.

This chart shows create → freeze catalog → broadcast full snapshot → end/leave on the Dart game server.

Concepts

PieceRole
match/createPractice stub: human caller + AI seat; freezes catalog via FastAPI service.
MatchRuntime.catalogByIdPrivate freeze — not on the wire.
Full snapshotEvery broadcast replaces client mirror when version is newer.
callerUserId / arenaIdWho called the match; where it is played.
RoomRegistryconnectionId ↔ room (matchId) + userId.

Step-through

  1. Client authenticates on Dart ws/authuser.
  2. match/create → Dart batch-fetches designs → stores freeze → returns + broadcasts snapshot (phase: playing).
  3. match/end (caller) → phase: ended + result.
  4. match/leave unsubscribes; empty room may end the match.
